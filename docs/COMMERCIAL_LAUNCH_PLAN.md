# Коммерческий запуск Telecom Manager

Состояние на 1 октября 2026 года. Код облачного режима и мобильного приложения
подготовлен; общий сервер и платёжный кошелёк ещё не подключены.

## Реализовано

### Текущая организация и режимы сервера

- [x] Первичная организация отмечается legacy; её синхронизация не ограничена
  подпиской. Self-hosted сервер работает без оплаты.
- [x] Новая облачная регистрация получает отдельную организацию и пробный период.
- [x] Синхронизация облака проверяет активность подписки; при окончании данные
  сохраняются, а синхронизация приостанавливается.
- [x] Облачные организации изолированы от таблиц legacy-веб-сайта. Доступ к
  общей веб-панели закрыт для cloud-only аккаунтов, пока в ней нет фильтрации
  по организациям.
- [x] Подготовлен отдельный Docker Compose для облака: порт `127.0.0.1:8001`,
  отдельные контейнеры и том PostgreSQL. Его можно запустить рядом с текущим
  сайтом на порту `8000`.
- [x] Docker-сборка исключает `.env`, Git-историю, базы и локальные файлы.

### Подписки и ЮMoney

- [x] Настраиваемые месячный и годовой тарифы, пробный срок, статус и дата
  окончания.
- [x] Внешняя страница оплаты с уникальной меткой заказа.
- [x] Подпись, валюта и сумма уведомления проверяются; повторное уведомление
  не продлевает доступ второй раз.
- [x] Ссылки на оплату истекают; подписанная задержанная квитанция всё равно
  учитывается.
- [x] Подписанный callback может пересылать неизвестные метки в pmguard, чтобы
  сохранить работу нескольких проектов с одним кошельком.
- [x] В Android-версии 1.1.1 администратор видит историю до 50 платежей;
  статус обновляется после возврата из браузера.
- [ ] Фискальные чеки не формируются. Перед коммерческим приёмом денег нужно
  определить юрлицо/налоговый режим и подключить нужную кассу или фискализацию.

### Android и Google Play

- [x] APK и App Bundle версии 1.1.1 собраны и опубликованы в
  [GitHub Release](https://github.com/magomedov1009/telecom-manager/releases/tag/android-v1.1.1).
- [x] Добавлены страницы конфиденциальности и удаления аккаунта.
- [x] Документация учитывает ограничения Google Play для внешней оплаты;
  первый релиз через Play подготовлен для России.
- [ ] Не завершены карточка приложения, графика, адрес поддержки, настройки
  Play Console и закрытое тестирование.

## Осталось до запуска общего облака

- [ ] Выбрать отдельный HTTPS-поддомен и настроить DNS/прокси на текущем VPS
  (или выбрать другой VPS); проверить свободные память и диск.
- [ ] Создать облачный `.env`: новые пароли БД и приложения, `HOSTING_MODE=cloud`,
  номер кошелька, цены и секрет уведомлений.
- [ ] Указать текущий callback pmguard в `YOOMONEY_FALLBACK_NOTIFICATION_URL`.
- [ ] Развернуть облачный Compose с пустой отдельной базой; проверить регистрацию,
  изоляцию двух организаций, синхронизацию, истечение подписки и восстановление
  после оплаты.
- [ ] Только после проверки переключить единственный callback ЮMoney на
  `https://<поддомен>/api/billing/yoomoney/notification`.
- [ ] Настроить внешние резервные копии и проверку восстановления.
- [ ] В Play Console ограничить первую публикацию Россией; для иных стран
  заранее проверить и включить подходящую программу оплаты.

## Защита текущей организации

- Не менять `HOSTING_MODE` работающего self-hosted сервера на `cloud`.
- Облако всегда запускается с отдельным контейнером PostgreSQL и отдельным томом.
- Перед обновлением действующего сайта делать резервную копию его базы.
- Секреты не добавлять в GitHub, APK или чат; хранить только в `.env` сервера.
