# Коммерческий запуск Telecom Manager

## Неприкосновенность действующей системы

- Текущая первая организация помечается как **legacy**: синхронизация для неё
  бессрочная и не зависит от тарифа.
- Ни одна миграция не удаляет клиентов, подключения, материалы, склады или
  пользователей.
- Перед развёртыванием на рабочем сервере обязательно создаётся резервная
  копия PostgreSQL и проверяется её восстановление на отдельной базе.

## Этап 1. Основа облачного доступа

1. Ввести для каждой облачной организации отдельную подписку: пробный период,
   месячный и годовой тарифы, срок действия и статус.
2. Отделить общий облачный сервер от self-hosted установки через `HOSTING_MODE`.
   На собственном сервере клиента подписка не требуется.
3. Дать приложению API статуса подписки и безопасную внешнюю ссылку на оплату.
4. Не блокировать уже подключённые организации на этапе внедрения.

## Этап 2. Первая настройка нового приложения

1. Убрать демонстрационных провайдеров из **новой** локальной базы.
2. Показать мастера: организация → владелец → свой провайдер → склад.
3. Существующие установки не изменять: их локальные записи и провайдеры
   сохраняются.
4. Оставить добавление нескольких провайдеров для компаний, работающих с
   несколькими операторами.

## Этап 3. ЮMoney

1. Создать внешнюю страницу тарифов и оплаты.
2. Передавать в ЮMoney уникальный номер заказа и идентификатор организации.
3. Принимать только серверное уведомление ЮMoney, проверять подпись и сумму.
4. Продлевать доступ идемпотентно: повторное уведомление не должно продлить
   подписку дважды.
5. Хранить историю платежей и выдавать чек/статус в личном кабинете.

## Этап 4. Правила доступа

1. Активная оплата или пробный период дают облачную синхронизацию.
2. После окончания подписки данные не удаляются. Локальная работа и просмотр
   сохраняются, серверная синхронизация приостанавливается.
3. При продлении доступ восстанавливается без переноса данных.
4. Собственный сервер работает без проверки облачной подписки.

## Этап 5. Google Play

1. Подготовить App Bundle (`.aab`), карточку приложения, скриншоты, политику
   конфиденциальности и удаление аккаунта.
2. Провести закрытое тестирование на нескольких новых организациях.
3. Публиковать только после проверки актуальных правил Google Play для
   внешней оплаты по ссылке, поскольку правила могут меняться.
