# Мобильная архитектура Telecom Manager

## Цель

Одно Android-приложение поддерживает два режима:

1. Локальный — SQLite на устройстве, работа без регистрации и интернета.
2. Командный — та же локальная SQLite плюс синхронизация с выбранной организацией на сервере.

Локальная база всегда является рабочим слоем приложения. Сервер не нужен для открытия экранов или создания операции.

## Изоляция организаций

Каждая бизнес-запись содержит `organization_id`. Организация отделяет данные разных городов и самостоятельных компаний. Сервер обязан проверять организацию по токену пользователя, а не доверять идентификатору из запроса.

Роли внутри организации:

- owner;
- admin;
- manager;
- installer.

## Идентификаторы и версии

- Новые мобильные и серверные записи используют UUID v7.
- `version` увеличивается при каждом изменении.
- `updated_at` хранится в UTC.
- Удаление мягкое через `deleted_at`.
- `sync_state`: `pending`, `synced`, `conflict`.

UUID позволяет телефону создавать записи без связи и без конфликтов последовательных ID.

## Очередь синхронизации

Каждая локальная запись и изменение создаются в одной SQLite-транзакции с элементом `sync_queue`.

Элемент очереди содержит:

- организацию;
- тип и ID сущности;
- операцию `upsert` или `delete`;
- JSON-снимок;
- число попыток и последнюю ошибку.

Повторное изменение одной сущности заменяет её старый элемент очереди. Отправка должна быть идемпотентной.

## План sync API

Следующий серверный контракт:

- `POST /api/v1/auth/login`;
- `POST /api/v1/sync/push`;
- `GET /api/v1/sync/pull?cursor=...`;
- `POST /api/v1/organizations`;
- `POST /api/v1/invitations`;

`push` принимает пакет изменений и возвращает подтверждённые версии или конфликты. `pull` возвращает изменения после курсора организации.

## Разрешение конфликтов

- Финансовые и складские транзакции после синхронизации не перезаписываются: исправление создаётся отдельной компенсирующей операцией.
- Справочники используют последнюю подтверждённую версию с ручным выбором при одновременном изменении.
- Подключение блокируется конфликтом, если одновременно изменены его материалы или финансовое распределение.

## Этапы

1. Локальная организация, склад, приход и очередь — текущий этап.
2. Локальные подключения, клиенты и списание материалов.
3. Локальные финансы и отчёты с общими тестовыми формулами.
4. Multi-tenant API на FastAPI и UUID-миграция сервера.
5. Авторизация, приглашения и двусторонняя синхронизация.
6. Резервное копирование, восстановление и сборка подписанного APK.
